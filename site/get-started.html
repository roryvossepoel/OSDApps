Your first deployment

Three steps. One normal deployment.

Follow a practical online WinPE example and stage three built-in apps before the first Windows boot.

Release candidate OSDStage 1.0.0-rc4 on the PowerShell Gallery. Use -AllowPrerelease to install the preview.
01
On the target PC · Online WinPE

Install from the PowerShell Gallery.

Apply Windows first, then run OSDStage before the first Windows boot, with internet access and PowerShellGet 1.6 or later available. These examples use OSDCloud because that is the workflow OSDStage was designed around, but OSDCloud itself is not required.

PowerShell
Install-Module OSDStage -Repository PSGallery -AllowPrerelease -Force -ErrorAction Stop
Import-Module OSDStage -Force -ErrorAction Stop

No module copy on a USB drive is needed. The optional OSDCloud-labeled USB cache is detected automatically.

02
Same target PC · WinPE

Choose your apps.

Add only what this device needs. Built-in app integrations are evergreen during online acquisition, so the supported vendor content is resolved when the deployment runs.

PowerShell
Add-OSDStageMicrosoft365Apps `
    -Channel MonthlyEnterprise `
    -Language en-us

Add-OSDStageGoogleChromeEnterprise -Architecture x64
Add-OSDStageAdobeAcrobatUnified -Architecture x64

These commands stage the selection. Installation happens during SetupComplete. If the same apps are also managed by Intune or another MDM/application platform, keep them assigned there for lifecycle and reset scenarios and align detection so it recognizes the version OSDStage installs.

03
Optional validation · same WinPE session

Validate before first boot.

This check is optional, but recommended while testing or building your deployment. It validates the staged queue before the first Windows boot.

PowerShell
Test-OSDStageDeployment -ThrowOnFailure |
    Format-List Valid, OfflineReady, NetworkRequired, PackageCount

Expect Valid: True and PackageCount: 3 on this example. OfflineReady: False is normal when content still needs to download. Once you are confident in your workflow, you can continue directly with your normal deployment restart without running this check every time.

Keep the PC online until OOBE appears. If you use the optional USB cache, leave it connected. SetupComplete acquires content as needed and installs your selections in order.

Your deployment, recorded

Open your delivery report.

After SetupComplete, open %ProgramData%\OSDStage\Results\DeliveryReport.html. Review app results, component details and attention items. The matching JSON is there too.

See what the report tells you →
Where can I see the result?

On the deployed Windows device, after SetupComplete:

PowerShell
$result = Get-Content "$env:ProgramData\OSDStage\Results\Latest.json" -Raw |
    ConvertFrom-Json
$result | Format-List Status, SuccessfulPackageCount, FailedPackageCount
$result.Packages | Format-Table Id, Status, ExitCode

Reaching OOBE alone does not prove every package succeeded.
